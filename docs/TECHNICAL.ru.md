# Технические сведения

Эта справка предназначена для тех, кто хочет разобраться в устройстве индикатора. Для обычной установки используйте ../README.ru.md.

## Исследование интерфейсов


В доступном файловом окружении проверены Mint 22.3, Cinnamon 6.6.9, kernel 7.0.0-38-generic, DMI board_name TM2107. У `redmi-wmi` есть привязанное WMI-устройство GUID 46C93E13-EE9B-4262-8488-563BCA757FEF и input-каталог. `/sys/firmware/acpi/platform_profile` и `/sys/class/platform-profile` отсутствуют. Интерфейса текущего режима в каталоге устройства нет. В hwmon нет обнаруженного интерфейса пары PPT Fast/Slow. RAPL и governor не считаются доказательством OEM-режима.

Исследованный дамп ACPI `SSDT7.dsl`, строки около 465–505: EV20/0x16 делает цикл STNM 2 → 1 → 3 → 2, вызывает ECWT и HPTC. Эти методы пакет не вызывает.

Изучен [upstream redmi-wmi.c](https://github.com/torvalds/linux/blob/master/drivers/platform/x86/redmi-wmi.c): драйвер преобразует события OEM-режима в KEY_PERFORMANCE и не предоставляет API чтения/записи platform_profile. Событие клавиатуры не даёт начального состояния после входа и не заменяет чтение PPT. Это upstream-источник; точное совпадение с исходниками Ubuntu-сборки 7.0.0-38 не подтверждено, локально исходник драйвера не найден.

Изучен [RyzenAdj lib/api.c](https://github.com/FlyGoat/RyzenAdj/blob/master/lib/api.c): получение таблицы требует запросов SMU. `--info` не устанавливает лимиты, но **не является строго пассивным чтением оборудования**. Из прошлой беседы подтверждён fallback к /dev/mem; в текущем ограниченном окружении /dev/mem недоступен, прямую аппаратную проверку выполнить нельзя. Строго read-only штатный API текущего режима не найден. Установка ryzen_smu, чтение EC/debugfs и непроверенные WMI-методы не предлагаются.

Поэтому выбран отдельный systemd oneshot-сборщик: фиксированная копия ryzenadj, единственный аргумент `--info`, очищенное окружение, тайм-аут 3 секунды, stderr отброшен, stdout разобран по `|` с точным именем строки. Апплет работает без root и читает только `/run/redmi-mode/status.json`. Файл заменяется атомарно, каталог принадлежит root. Нет sudo, pkexec, D-Bus-команд от клиента, setuid, capabilities на бинарнике или правил NOPASSWD. Коллектор запрещает аргументы и проверяет владельцев/права своих путей. Изоляция systemd ограничивает файловые записи; доступ к железу остаётся привилегированным. Это уменьшает поверхность доступа, но не делает RyzenAdj аппаратно read-only.

## Реализация

В этой версии выбран значок из трёх вертикальных делений одинаковой высоты. Апплет читает небольшой файл раз в 2 секунды асинхронно; служба запускает Python и RyzenAdj примерно раз в 5–8 секунд. Данные старше 20 секунд либо более чем на 2 секунды из будущего отвергаются. Фактическое влияние на батарею не измерено.

Служба systemd ограничивает файловые записи, но намеренно не использует PrivateDevices и ProtectKernelTunables: RyzenAdj может требоваться доступ к /dev/mem и конфигурации PCI. Это не аппаратная read-only изоляция. Установка не выдаёт обычному пользователю доступ к EC, PCI или памяти, не добавляет NOPASSWD и не устанавливает дополнительные модули ядра.

Привилегированная копия RyzenAdj находится в /usr/local/libexec/redmi-mode/ryzenadj и не обновляется автоматически вместе с /usr/local/bin/ryzenadj. После проверки новой версии копию обновляют вручную. Каталоги /usr/local, /usr/local/libexec, /usr/local/libexec/redmi-mode и исполняемый файл должны принадлежать root и быть недоступными для групповой/общей записи. Перед установкой неизвестной сборки проверьте её происхождение и зависимости; на исследованной машине зависимости находились в системных каталогах.

## Проверки

```sh
python3 -m unittest discover -s tests -v
LC_ALL=en_US.UTF-8 LANGUAGE=en cjs tests/test_applet.js "$PWD" en
LC_ALL=ru_RU.UTF-8 LANGUAGE=ru cjs tests/test_applet.js "$PWD" ru
systemd-analyze verify systemd/redmi-mode.service systemd/redmi-mode.timer
```

22.10.2026 прошли 7 Python-тестов и 65 CJS-проверок для каждого языка (английского и русского). Проверены парсинг, границы классификации, ошибки и тайм-ауты, фиксированные аргументы команды, DMI-защита, атомарная публикация, отказ небезопасным путям, устаревание, асинхронное чтение и очистка ресурсов. CJS-тест использует реальные Gio/Cancellable, но подставляет оболочку Cinnamon. Проверка unit-файлов не сообщила об ошибках этих двух файлов; были предупреждения о постороннем syncthing@.service.

После установки на ноутбуке подтверждены успешный сбор данных 30/10 Вт, активный таймер и загрузка апплета в живой Cinnamon. Пользователь выбрал и подтвердил вид значка №6. На зарядке проверен полный цикл Fn+K: 35/20 → 60/50 → 65/54 → 35/20 Вт. Эти пары распознаются с допуском ±2 Вт по каждому лимиту. Оба лимита должны соответствовать одной паре; подключение зарядки само по себе не определяет режим. Проверены границы диапазонов и отказ при смешении лимитов разных режимов. Полный цикл от батареи, переходы между сетью и батареей и сон/пробуждение отдельно не проверены. Результат по PPT — оценка OEM-режима: сторонняя программа может изменить лимиты независимо от STNM.

GitHub Actions запускает Python-тесты, синтаксическую проверку JavaScript, проверку SVG/JSON и unit-файлов. Полный CJS-тест выполняется локально на Mint и не входит в Ubuntu-задание CI.

## Переводы

Подсказки, меню, названия режимов и ошибки используют gettext: исходные строки английские, русский каталог включён в папку апплета. Смена языка применяется после повторного входа в сеанс. Английский используется при отсутствии перевода.

Для изменения перевода отредактируйте `po/ru.po` и пересоберите включённый в пакет файл:

```sh
msgfmt --check po/ru.po -o applet/redmi-mode@local/locale/ru/LC_MESSAGES/redmi-mode@local-1.0.3.mo
```

Утилита msgfmt входит в пакет gettext (`sudo apt install gettext`). В Git должны попасть оба файла: исходный и скомпилированный. CI проверяет их соответствие. Для тестов нужны локали en_US.UTF-8 и ru_RU.UTF-8; список показывает `locale -a`. Локаль C отключает переводы gettext, даже если задано LANGUAGE=ru.

## Ограниченная мощность

Для наблюдавшейся пары 35/28 Вт добавлено отдельное состояние `limited`: Fast 33–37 Вт и Slow 26–30 Вт, после проверки обычных диапазонов. Значок — контуры трёх делений с горизонтальной чертой. Это описание лимитов, а не определение режима Fn+K и не диагноз зарядного устройства. Другие незнакомые пары остаются неизвестными; при ошибке чтения или устаревании данных это состояние не сохраняется.

В DSDT обнаружено, что HPTC выбирает политики с учётом условий адаптера и батареи, а отдельные ветви HDC2 используют 35/28 Вт и для режима 1, и для режима 3. Наблюдались переходы 35/28 ↔ 65/54 Вт при подключении часов к той же зарядке. Показания USB при наблюдавшемся переходе оставались 20 В / 5 А, поэтому они не доказывают изменение доступной мощности. После отключения часов 65/54 Вт оставались стабильными 32 секунды. Это согласуется с предположением о разделении мощности, но не доказывает его. Записи в оборудование и изменения разрешений не добавлены.
