# Автоматическое восстановление температурного предела 85 °C

[English](README.md) · [Русский](README.ru.md) · [Основная инструкция](../README.ru.md)

Для Redmi Book Pro 14 2022, плата TM2107, с уже установленным индикатором redmi-mode и RyzenAdj.

## Что делает

- Проверяет строку `THM LIMIT CORE` примерно каждые **30 секунд**.
- Если порог **выше 85 °C**, выполняет только `--tctl-temp=85` и повторным чтением проверяет результат.
- Не повышает более низкие пределы: например, 80 °C остаются 80 °C.
- Не задаёт мощность, частоты или режимы Fn+K.
- Запускает отдельную проверку после выхода из сна/гибернации.
- Использует `WakeSystem=no`: таймер не будит ноутбук из сна. При работающей системе проверки всё же расходуют некоторое количество энергии; влияние на батарею не измерено.

Это поддержка настройки с периодическим восстановлением, **не жёсткая гарантия непрерывного температурного потолка**. Прошивка может поднять лимит между проверками. После Fn+K или изменения питания он будет восстановлен на ближайшем цикле: обычно примерно за 30 секунд плюс время выполнения проверки. Температурный порог RyzenAdj также не гарантирует отсутствия кратких превышений фактической температуры.

Сам индикатор мощности остаётся непривилегированным читателем своего файла. Доступ к RyzenAdj у индикатора и контроля температуры сериализован общим файлом блокировки. Поэтому они не отправляют команды одновременно. Прямых EC/WMI-записей нет.

## Устройство установки

Исходные файлы `ryzenadj.service` и `redmi-mode.service` сохраняются. Добавляются только:

- `/usr/local/libexec/redmi-thermal-guard/guard.py` — проверка температуры;
- `/etc/systemd/system/ryzenadj.service.d/85c-guard.conf` — замена одноразового вызова на проверку;
- `/etc/systemd/system/redmi-mode.service.d/30-thermal-lock.conf` — общая блокировка со сборщиком;
- `/etc/systemd/system/ryzenadj.timer` — расписание;
- `/usr/lib/systemd/system-sleep/85-redmi-thermal-guard` — проверка после сна.

Используется уже установленная, принадлежащая root копия `/usr/local/libexec/redmi-mode/ryzenadj`. Общие правила NOPASSWD, setuid или доступ пользователя к памяти/PCI не добавляются.

## Установка

Это дополнительный компонент: обычная установка индикатора его не включает. Сначала установите и проверьте индикатор по [основной инструкции](../README.ru.md).

Откройте терминал в папке `thermal-guard` (либо выполните `cd thermal-guard` из корня проекта). Проверьте, есть ли служба ограничения температуры:

```sh
systemctl cat ryzenadj.service
```

Если службы нет, установите приложенный шаблон. Делайте это только для новой установки, не заменяя существующую службу:

```sh
sudo install -o root -g root -m 0644 systemd/ryzenadj.service /etc/systemd/system/ryzenadj.service
```

Если служба уже существует, этот шаг пропустите. Установщик рассчитан на исходную службу в `/etc/systemd/system/ryzenadj.service`. Для службы из другого места сначала изучите её конфигурацию.

Изучите файлы этого компонента и выполните в той же папке:

```sh
sudo sh ./install.sh
```

Установка требует существующих `ryzenadj.service`, `redmi-mode.service` и активного `redmi-mode.timer`. При обнаружении собственных уже установленных файлов она останавливается, чтобы не заменять настройки молча. При ошибке первоначального запуска новые файлы удаляются, исходная служба восстанавливается. Резервные копии исходных unit-файлов сохраняются в отдельной папке `/var/tmp/redmi-thermal-before-*`, путь печатается при установке.

## Проверка

```sh
systemctl status ryzenadj.timer --no-pager
cat /run/redmi-mode/thermal.json
sudo journalctl -u ryzenadj.service -n 20 --no-pager
```

Таймер должен быть `active (waiting)`. В JSON ожидаются `"ok": true` и `"limit": 85.0` либо более низкое число. Поле `timestamp` — время начала последней проверки; `corrected: true` означает, что на этой проверке пришлось восстановить порог. Прошивка всё ещё может изменить лимит после записанного измерения: JSON сообщает результат последней проверки, а не непрерывную аппаратную гарантию.

1. Нажмите Fn+K и подождите около 35 секунд.
2. Проверьте JSON и журнал. При сбросе заводского порога должна появиться запись о восстановлении.
3. Повторите для остальных режимов, подключения/отключения зарядки и сна/пробуждения.

Служба типа oneshot между проверками может отображаться как `inactive (dead)` — это нормально. Постоянно активным должен быть **таймер**. Если проверка не удалась, служба сообщит об ошибке и повторит попытку на следующем цикле; ошибка не выдаётся за действующее ограничение.

## Откат к старой одноразовой службе

Удаляйте этот компонент **до удаления основного индикатора**: он использует установленную с индикатором копию RyzenAdj и общую папку временных данных.

```sh
sudo systemctl disable --now ryzenadj.timer
sudo systemctl stop ryzenadj.service
sudo rm -f /etc/systemd/system/ryzenadj.timer
sudo rm -f /etc/systemd/system/ryzenadj.service.d/85c-guard.conf
sudo rm -f /etc/systemd/system/redmi-mode.service.d/30-thermal-lock.conf
sudo rm -f /usr/lib/systemd/system-sleep/85-redmi-thermal-guard
sudo rm -f /usr/local/libexec/redmi-thermal-guard/guard.py
sudo rmdir /usr/local/libexec/redmi-thermal-guard
sudo systemctl daemon-reload
sudo systemctl restart ryzenadj.service
```

После отката исходная служба снова задаёт 85 °C однократно. Сборщик индикатора продолжит работать. Файл `/run/redmi-mode/thermal.json` можно удалить вручную; он больше не будет обновляться.

## Тесты

```sh
python3 -m unittest discover -s tests -v
```

Шесть тестов проверяют восстановление 98→85, сохранение более низких пределов, отказ при неверных данных, неподтверждённый результат команды, фиксированные аргументы/окружение и ошибки/тайм-ауты. Они не обращаются к реальному оборудованию.

При установке 27.10.2026 первое аппаратное чтение показало 98 °C, после применения настройки повторное чтение подтвердило 85 °C. После нажатия пользователем Fn+K очередная автоматическая проверка обнаружила сброс до 90 °C, восстановила 85 °C и подтвердила результат. Полная приёмка всех сочетаний Fn+K, питания и сна требует дополнительных проверок на ноутбуке.
